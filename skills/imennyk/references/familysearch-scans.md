# FamilySearch через headless Chrome на сервері

Скани справ лежать на FamilySearch за логіном і без публічного API. Агент працює з ними через справжній Chrome, що постійно запущений на основному хості й уже залогінений. Цей документ — як його підняти, як у нього зайти, як витягувати з FamilySearch номери зображень, посилання й повнорозмірні скани, і які там підводні камені. Що робити зі сканами далі — [scan-extraction.md](scan-extraction.md).

## Що стоїть на хості
| Що | Як |
|---|---|
| Chrome for Testing | `/opt/chrome`, симлінк `/usr/local/bin/chrome-headless` (встановлено `pnpm dlx @puppeteer/browsers install chrome@stable --path /opt/chrome`) |
| віртуальний дисплей | `xvfb.service`, дисплей `:99` |
| Chrome | `chrome-headless.service`: звичайний (не `--headless`) Chrome на дисплеї `:99`, DevTools на `127.0.0.1:9222`, профіль `/var/lib/chrome-profile` |
| вхід для людини | `x11vnc.service` (`127.0.0.1:5900`) і `novnc.service` (`127.0.0.1:6080`); назовні нічого не відкрито |

Профіль на диску: куки FamilySearch переживають перезапуск Chrome і сервера. Логін зроблено один раз вручну з галочкою «Remember me».

Агенти (Claude Code, Cursor) підключаються до `http://127.0.0.1:9222` по CDP: `chromium.connectOverCDP`, puppeteer `connect`, або «сирий» WebSocket з `webSocketDebuggerUrl` зі `http://127.0.0.1:9222/json/list` (Node 24 має глобальний `WebSocket`). Порт слухає лише localhost: з ноутбука він доступний через `ssh -N -L 9222:127.0.0.1:9222 <хост>`.

## Нюанси
- **Не `--headless`.** FamilySearch (захист від ботів) віддає «Access Denied, Error 15» на User-Agent з `HeadlessChrome`. Тому Chrome запущено не headless, на Xvfb, з `--user-agent="… Chrome/156.0.0.0 Safari/537.36"` (без `Headless`) і `--disable-blink-features=AutomationControlled`. Перевірка: `curl -s 127.0.0.1:9222/json/version` має показати звичайний `Chrome`, а не `HeadlessChrome`.
- **Прапорці для звичайного режиму на сервері.** `--no-sandbox` (root), `--password-store=basic --no-first-run --no-default-browser-check` — без них Chrome на дисплеї зависає на старті на D-Bus/keyring і не відкриває порт DevTools.
- **Chrome 136+ ігнорує `--remote-debugging-port` з профілем за замовчуванням.** Тому профіль окремий (`--user-data-dir=/var/lib/chrome-profile`).
- **Вікно «трансляції» DevTools (`chrome://inspect`) не передає клавіатуру** у поля введення: увійти в обліковий запис так не вийде. Для людини — noVNC: `ssh -N -L 6080:127.0.0.1:6080 <хост>`, потім `http://localhost:6080/vnc.html` (пароля немає). Вставляти текст — через панель noVNC.
- **Сесія може злетіти** (неактивність, перевірки безпеки). Ознака: у вкладці FamilySearch сторінка входу замість переглядача, або відсутній `view=explore`. Тоді попросити власника увійти знову через noVNC: Chrome пам'ятає логін і пароль (профіль `/var/lib/chrome-profile`), поля форми заповнюються самі, тож достатньо одного кліку «Sign in». Агент входить сам: `node tools/familysearch-scan/login.mjs` бере `FAMILY_SEARCH_USER` і `FAMILY_SEARCH_PASSWORD` з `.env` репозиторію Grapa (рішення власника 2026-11-05), вводить їх через CDP і друкує лише «signed in» або помилку; пароль містить `#` і `$`, тому файл читається як є, а не через `--env-file`. Значення ніде не друкуються й не зберігаються.
- **Не виймати куки й токени сесії з браузера** у файли чи змінні середовища. Усе, що потребує сесії, робиться всередині браузера (див. нижче), а на диск лягають лише скани.
- **`fetch()` зі сторінки на `sg30p0.familysearch.org` (CORS) не проходить**, а `<img>` — проходить. Тому скани беремо тайлами через `Image` і CDP `Network.getResponseBody`, а не через `fetch`.
- Нову вкладку відкривати через `PUT http://127.0.0.1:9222/json/new?<url>` і після роботи закривати (`/json/close/<id>`), щоб не накопичувати їх.

## Номери зображень і посилання
Група зображень (DGS, id на кшталт `TH-7791-147528-782-7`) — це послідовність зображень справи; кожне — розворот книги. Посилання на сторінку цитати — `https://www.familysearch.org/ark:/61903/3:1:<ark>?view=explore&groupId=<група>&lang=uk`.
- **Номер зображення** — у переглядачі: «Image 48 of 68» (у вікні перегляду це поле «Enter Image number», `input[type=number]`; у DOM також `aria-label="Image Viewer"`). Саме він — `citation.page` (`record-sheet.md`, «Скан і посилання в кожному рядку»). Друкований номер аркуша на самій сторінці (наприклад «42» угорі праворуч) — інша річ: його записують у нотатці запису, але сторінка цитати — номер зображення.
- **Ark зображення (`3:1:3QHK-…`) непрозорий.** Із номера групи й номера зображення посилання не обчислюється: `dgs:<група>_000NN` — це інший ідентифікатор, з нього ark не випливає.
- **Як зібрати ark усіх зображень групи.** Відкрити перше зображення групи у вікні перегляду й проходити групу клавішею «вправо» (`ArrowRight` через CDP `Input.dispatchKeyEvent`); після кожного кроку читати `location.href` і номер зі «Image N of M». Результат — `import/<справа>/scans.tsv` з колонками `scan` (`n_048`), `ark`, `url`. Адреса оновлюється з невеликою затримкою, тож перед читанням почекати, поки номер зображення зміниться.
- **Ключ групи** — з `groupId=` в адресі; його ж видно в заголовку вкладки («Церковні записи, Волинська духовна консисторія (ф. 35), 1918-1939: …»), там і діапазон дат та види записів справи.

## Повнорозмірний скан
Переглядач показує зображення у вигляді піраміди тайлів (Deep Zoom): `https://sg30p0.familysearch.org/service/records/storage/deepzoomcloud/dz/v1/apid:<id>/image_files/<рівень>/<колонка>_<рядок>.jpg`. `apid` — внутрішній ідентифікатор зображення, його видно лише в адресах тайлів у відкритому переглядачі, а не в ark. Рівень 9 — мініатюра, найвищий (у наших справах 13) — повна роздільність (~6200×5000 px). Тайл 256×256 px, між тайлами перекриття 1 px (257/258 px).

Помічник [`tools/familysearch-scan/scan.mjs`](../tools/familysearch-scan/scan.mjs):
```
node tools/familysearch-scan/scan.mjs '<посилання на зображення>' /var/tmp/<справа>/n048.jpg
```
Що він робить:
1. Відкриває посилання у новій вкладці й чекає тайли переглядача, з першого виймає `apid`.
2. У сторінці пробує `Image` для рівнів 10, 11, … (максимальний — перший, що не існує, мінус один) і для сітки `колонка×рядок` на цьому рівні.
3. Завантажує всі тайли найвищого рівня як `<img>` (кеш вимкнено) і читає їхні байти з CDP через `Network.getResponseBody` (куки з браузера не виходять).
4. Склеює тайли ImageMagick: `-chop 1x1` на всі, крім першої колонки й першого рядка (перекриття), `+append`, `-append`.
Результат — JPEG повного розміру (~6 МБ, ~15 секунд на зображення). Скани лежать у `/var/tmp/<справа>/`, у git не йдуть (на основному хості `/tmp` у пам'яті).

Далі скан читають збільшеними фрагментами за [scan-extraction.md](scan-extraction.md), крок 3. Для огляду спершу зменшена копія (`magick n048.jpg -resize 22% n048_s.jpg`, ~1360 px завширшки), потім смуги з потрібних місць.

## Дерева (Family Tree)
Той самий залогінений Chrome віддає й родоводи: вкладка на `familysearch.org` викликає `fetch('/service/tree/…')` і повертає JSON; куки й токени не виходять з браузера (`/platform/…` без токена дає 401, ним не користуємось). Адреси, обхід поколінь і правило про живих — [familysearch-tree.md](familysearch-tree.md), код — `src/familysearch/tree/browser.ts`.

## Коли щось не працює
| Ознака | Причина й що робити |
|---|---|
| `curl 127.0.0.1:9222/json/version` порожньо | Chrome не слухає порт: `systemctl status chrome-headless`, `journalctl -u chrome-headless`; перевірити, що `xvfb.service` активний |
| «Access Denied, Error 15» | User-Agent містить `Headless` або Chrome запущено з `--headless`: перевірити `json/version` |
| `no tile base (not logged in or viewer failed)` у помічнику | сесія злетіла або зображення не відкрилося: відкрити вкладку з тим посиланням і подивитися, що на сторінці |
| `tiles N/M` | не всі тайли встигли завантажитися: повторити; перевірити мережу |
| `chrome://inspect` порожній | немає тунелю на 9222 або не додано `localhost:9222` у Configure |
