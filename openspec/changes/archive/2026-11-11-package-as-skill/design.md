# Дизайн

## Context

Код — TypeScript у `src/`, що запускається через `tsx` (`pnpm indexing`, `pnpm gortach`, `pnpm familysearch:tree`); CLI виконуються на рівні модуля. `src/indexing/db.ts` читає міграції з `join(import.meta.dirname, "migrations")`. `src/indexing/cli.ts` записує в прогін SHA останнього коміту `docs/scan-extraction.md` (версія порядку читання) через `git log` з кореня репозиторію. Залежності виконання — лише `zod` і `yaml`; SQLite — вбудований `node:sqlite`. `tools/*.mjs` — JS-скрипти, що кличуть `magick` і Chrome по CDP, поза лінтом.

## Goals / Non-Goals

**Goals:** скіл працює з клону чи з копії, яку зробив інсталятор, маючи лише Node 24; один код у `src/` для розробки й для скіла.

**Non-Goals:** MCP-сервер; переписування `tools/`; зміна поведінки CLI.

## Decisions

1. **Три зібрані файли, а не один диспетчер.** esbuild збирає кожен `src/**/cli.ts` в окремий ESM-файл (`platform: node`, `format: esm`, `bundle`, `zod` і `yaml` усередині, `node:*` зовнішні). CLI лишаються як є, без нового рівня підкоманд. Альтернатива — один `imennyk.mjs` з підкомандами — вимагала б переробити CLI, що виконуються при імпорті.
2. **Міграції копіюються поруч зі скриптами** (`scripts/migrations/`). `import.meta.dirname` у зібраному файлі — тека `scripts/`, тож `db.ts` знаходить їх без змін коду. Альтернатива — вшити SQL у бандл — змінила б `db.ts` і тести міграцій.
3. **Збірка — бібліотечна функція** `src/skill/build.ts`: повертає файли (шлях → вміст) без запису на диск; тонкий `src/skill/cli.ts` (`pnpm build:skill`) їх пише. Тест кличе ту саму функцію і порівнює з файлами в `skills/imennyk/scripts/`. Збірка детермінована: без мінімізації, без sourcemap, без часу збирання в тексті.
4. **Зібрані файли комітимо.** Інсталятори скілів беруть теку з GitHub як є; npm-пакет додав би процес випуску.
5. **Версія порядку читання** — SHA останнього коміту `skills/imennyk/references/workflow.md`: `git -C <тека скрипта> log -1 --format=%H -- :/skills/imennyk/references/workflow.md`. Працює і з `src/`, і з `scripts/`; поза git (копія інсталятора) — `undefined`, як і зараз без git.
6. **Документи за читачем.** У `references/` — те, що агент читає під час роботи; у `docs/` — мета, етапи, збирання скіла. Команди в документах скіла — `node <скіл>/scripts/<інструмент>.mjs …`, де `<скіл>` — тека `SKILL.md`; `pnpm …` лишається в `docs/` і `README.md` для розробки.
7. **Словники.** `*-khvorostiv` видаляються; `words-registers.tsv` і `patronymics.tsv` переїжджають у `references/dictionaries/` як довідка для читання (інструмент їх не читає, вимога «Словники справи»).
8. **Автор індексування.** Файл автора — поза справами й репозиторієм, бо він належить людині, а не справі: `$IMENNYK_OPERATOR`, інакше `$XDG_CONFIG_HOME/imennyk/operator.yaml`, типово `~/.config/imennyk/operator.yaml`. Шлях рахує чиста функція з середовища й домашньої теки; читання й запис — у шарі CLI. `run-start` і `familysearch-tree ingest` без файла відмовляють з текстом, що велить агентові спитати людину; `indexing operator --set` записує відповідь. У бібліотеці `operator` у `startRun` необов'язковий (старі прогони й тести без нього), обов'язковим його робить CLI. Колонка `run.operator` з CHECK проти порожнього рядка. `operator.yaml` у корені репозиторію — підпис власника; інструменти його не читають.
9. **Лінт.** `skills/imennyk/scripts/` — згенеровані й перенесені файли — у ignore ESLint і Prettier замість `tools/`.

## Risks / Trade-offs

- [Забули перезібрати] → тест свіжості в `pnpm test` падає, а `AGENTS.md` велить запускати `pnpm build:skill` після змін у `src/`.
- [Інша версія esbuild дає інший текст] → версія закріплена в `pnpm-lock.yaml`; тест і збірка йдуть однією версією.
- [`tools/` потребують ImageMagick і Chrome, а ядро — ні] → `SKILL.md` прямо каже, які кроки цього потребують; переписування — етап 3.
- [Шлях `:/…` у git неочевидний] → лише в одному місці, з коментарем.
