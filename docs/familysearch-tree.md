# Імпорт дерев FamilySearch
Як вносимо в криницю родоводи з FamilySearch Family Tree: предків однієї особи (корінь), яких бачить залогінений користувач. Це не індексування сканів, але шлях той самий: завантажити → локальна sqlite справи → внесення в криницю. Структура sqlite та сама, що в індексуванні ([scan-extraction.md](scan-extraction.md)), тож результат так само можна оглянути, а внесення так само відтворюване.

Інструмент — `pnpm familysearch:tree`, код у `src/genealogy/import/familysearch-tree/`. Журнал імпортів — [import/familysearch-trees.md](../../../import/familysearch-trees.md).

## Правило про живих: для всіх дерев
**З жодного дерева не вносимо живих людей.** Це стосується всіх родоводів: FamilySearch, GEDCOM, Gramps, таблиць. Правило одне, воно в коді: `src/genealogy/import/living.ts` (`livingState`, `LIVING_HORIZON_YEARS = 110`), і кожен імпорт дерев користується ним.

Людина внесена, лише якщо відомо, що вона померла. Порядок перевірки:
1. Джерело саме позначило її живою (`living` у FamilySearch, `_LIVING` / приватність в інших) — жива.
2. У джерелі записано смерть (дата або лише позначка «померла») — померла.
3. Є рік народження: народжені менш ніж 110 років тому — живі, раніше — померлі.
4. Ні прапорця, ні смерті, ні року народження — **невідомо**: не вносимо, а називаємо в звіті. Власник може дозволити таку людину за id (`--allow`).

Живі й невідомі лишають у файлах лише id і причину (`excluded`): ні імені, ні дат. Живі родичі в списках сім'ї (діти, подружжя) не потрапляють у файли ні як особи, ні як id у зв'язках. Сирі відповіді FamilySearch на диск не пишуться: у них сторінка особи має в списках сім'ї живих дітей з іменами. На диск лягають лише очищені записи.

Імпорт таблиць (`import:tree-sheet`) рахує ту саму межу: подія не пізніше `поточний рік − 110` або відома смерть. Прапорець `--cutoff` задає її вручну.

## Звідки беремо
Дані віддає сам FamilySearch залогіненому браузеру. Агент не бере ні куків, ні токенів: у вкладці Chrome на хості ([familysearch-browser.md](familysearch-browser.md)) виконується `fetch` тих самих адрес `/service/tree/…`, що й сайт, а назад іде тільки JSON. Адреси не публічні й можуть змінитися; без токена `/platform/…` дає 401, тож ними не користуємось.

| Що | Адреса (відносно `https://www.familysearch.org`) |
|---|---|
| родовід: предки по поколіннях | `/service/tree/tree-data/r9/portrait-pedigree/<id>?includeMarriages=true&numGenerations=8` |
| особа: імена, стать, народження, смерть, батьківські й шлюбні сім'ї | `/service/tree/tree-data/v8/person/<id>/details` |
| ідентифікатори прикріплених джерел | `/service/tree/tf/person/<id>/entityref?version=2` |
| самі джерела (назва, посилання на запис, дата) | `/service/tree/links/sources/<id>,<id>?readExternalData=true` |

Нюанси родоводу:
- Один виклик — **не більше 8 поколінь** (9 проходить, але дає ті ж 8, 10 — помилка). `ancestors[0]` — не батьки кореня, а сам корінь з подружжям; далі кожне покоління вдвічі більше.
- Глибші гілки добираємо: особу з останнього покоління, у якої є батьки (`parent1ParentIds` / `parent2ParentIds`), беремо новим коренем.
- **Той самий id може бути в кількох деревах** (подружжя ділить предків; корінь одного дерева — предок іншого). Обхід тримає одну картку на id, а внесення ідентифікує особу за цитатою (див. нижче), тож друге дерево лише дописує нове.
- Між викликами пауза 120 мс, обхід послідовний.

## Етапи
```bash
pnpm familysearch:tree fetch import/indexing/FamilySearch-tree --root GG22-75Z --root GG22-SQH
pnpm familysearch:tree ingest import/indexing/FamilySearch-tree --model <модель>
pnpm familysearch:tree enter import/indexing/FamilySearch-tree --actor "agent: …" --places import/indexing/FamilySearch-tree/places.json --dry-run
pnpm familysearch:tree enter … --apply
```
1. **fetch** — обхід предків кожного кореня, фільтр живих, очищені картки у `raw/tree-<корінь>.json`. Друкує, скільки осіб, скільки відсіяно як живих і як невідомих. `--allow <id>` дозволяє невідому особу.
2. **ingest** — кожен `raw/tree-*.json`, ще не прочитаний, стає прогоном (`run`) у `case.sqlite`. Особа, яка вже є в справі (з іншого дерева), вдруге не пишеться.
3. **enter** — план з sqlite (без PostgreSQL), потім одна транзакція. `--dry-run` відкочує. Кандидатів для місць, не зіставлених у `places.json`, друкує за назвою.

Як в індексуванні: проміжна база — `case.sqlite` справи, ідентифікатори локальні, `ddb_map` зв'язує їх з криницею після внесення.

## Папка справи
Одна справа — всі дерева FamilySearch: `import/indexing/FamilySearch-tree/` (нове дерево — нове читання в тій самій папці, як нова парафія в справі). Імена людей з родоводів у git не йдуть (`.gitignore`): комітиться лише `places.json` (зіставлення місць без персональних даних) і журнал `import/familysearch-trees.md`.

| Файл | Що |
|---|---|
| `raw/tree-<id>.json` | очищені картки дерева (`treeBundleSchema`); локально |
| `case.sqlite` | локальна база, схема індексування (міграції `src/genealogy/indexing/migrations/`); локально |
| `places.json` | `{"<id місця FamilySearch>": <id місця в криниці>}`; у git |

## Що куди лягає в sqlite
Таблиці ті самі, що в індексуванні; сумнівів (`doubt_word`) і вибірки (`sample`) немає: дані не читаємо зі сканів, а переносимо.

| FamilySearch | sqlite | Примітка |
|---|---|---|
| сторінка особи | `scan`: `name` = id особи (`GG22-75Z`), `url` = `…/tree/person/details/<id>`, розмір 1×1 | зображення немає; `scan` — це сторінка цитати |
| особа | `person` + `name_mention` | стать; ім'я українською формою (`uk`); дата народження — роки `birth_from/to`, `birth_qual` |
| ім'я | `given`, `patronymic`, `surname` | FamilySearch кладе «Іван Петрович» у ім'я: друге слово із закінченням по батькові (`-ович`, `-івна` …) — по батькові; інакше ім'я цілим. Немає прізвища — порожнє |
| ім'я латиницею | атрибут `note` «Latin: …» | |
| народження, смерть | `event` (`birth`, `death`) з `date_from/date_to/date_qual`, `place_id` | повні дати (міграція `0010`); смерть без дати («померла») подією не стає |
| шлюб | `event` `marriage` + `tie` `spouse` | один шлюб на пару; пара без події шлюбу — лише `tie` без події |
| батьки | `tie` `child` (особа = дитина, `other` = батько чи мати) | при події народження дитини — з `event_id` |
| місце події | `place`; за ключ — id місця FamilySearch | усі написання одного id (кирилиця, латиниця, польське) — одне місце; назва — найчастіша кирилична, решта — у `dict_entry`; стандартна назва, координати, id — атрибут `note` місця |
| прикріплене джерело | атрибут `url` особи: `[назва, дата](посилання)` | зазвичай запис метричної книги на FamilySearch |
| дата, яку не розібрано («до 1900») | атрибут `note` події «Date as written: …» | |

### Дати
- Формальна дата `+1946-06-28` — день, `exact`; `+1911-05` — цей місяць, `+1820` — цей рік (з 1 січня по 31 грудня), обидва `exact`, як рік документа в криниці.
- `A+1770` («прибл.») — рік ±2, `about`, як `ABT` у `ddb.doc_bounds`.
- Діапазони, «до», «після» в межі не перетворюються: текст дати лежить у `note`.
- Календар не перераховуємо.

## Внесення в криницю
Джерело — `FamilySearch Family Tree` (`source.type = tree`, сховище FamilySearch, `url = https://www.familysearch.org/tree`); воно одне на всі дерева. Створюється при першому внесенні, далі знаходиться за адресою.

| Об'єкт | Як |
|---|---|
| цитата | одна на особу: `page` = id особи, `url` = сторінка особи |
| особа | та, на яку вже веде цитата з цим id, — та сама згадка, вдруге не пишеться. Нова особа — рядок `person` + імена через словник `name` |
| подія | народження, смерть, шлюб з цитатою особи; `place_m` — текст місця, `place` — місце криниці, якщо id місця FamilySearch є в `places.json` |
| зв'язок | `child` і `spouse` через `event_tie` до події, якщо вона є; інакше окремо; цитата — сторінка особи, на якій він записаний |
| атрибути | посилання на прикріплені джерела й латинське ім'я — атрибути особи з цитатою |

Місця криниці зіставляємо **за назвою і координатами**, а не за назвою: у криниці десятки сіл з однаковими назвами (відомі дублікати). У `places.json` — лише певні збіги (координата в межах ~1 км і назва); решта лишається текстом у `place_m`, список друкує `enter`.

Межі id нового, як і в інших імпортах, записуємо в журнал (журнал змін вимкнено).

## Що поки не вносимо
- Нащадків і братів-сестер предків (їх можна додати окремою опцією: у `details` вони є в списках сім'ї).
- Нотатки, спогади й фото особи (на цих деревах їх немає).
- Місця як нові об'єкти криниці (лише зіставлення з наявними).
- Живі та невідомі за правилом вище.

## Перевірка після запису
1. Кількість: осіб, подій, зв'язків, цитат — як у плані (`enter --dry-run`); повторний запуск дає `known` = усім особам і нічого не пише.
2. Картки кількох осіб: ім'я, дати, місце, батьки, цитата з правильною сторінкою.
3. Прізвище, що стоїть як ім'я, і ім'я з двох слів без по батькові — ознака хибного поділу імені.
4. Дитина не народжується після смерті батьків (`data-entry.md`, розділ 6).

## Підводні камені
- **Сесія злетіла**: `fetch` одразу падає з поясненням (401/403). Увійти знову через noVNC ([familysearch-browser.md](familysearch-browser.md)).
- Корінь і подружжя: `ancestors[0]` — не батьки. Обхід це враховує; перевіряти не треба, лише знати, читаючи сирий JSON.
- FamilySearch називає місце то кирилицею, то латиницею, то спотворено («Жукув, миąкзин»): такі назви лишаються як є, зіставлення з криницею — вручну.
- Прапорець `living` у FamilySearch може бути хибно `false` для щойно померлої людини без дати смерті; тому рахуємо ще й смерть і рік народження.
