# Іменник: огляд

## Мета
Іменник — відкритий інструмент для індексації людей в архівних документах (метричні книги, сповідні розписи, ревізькі казки, дерева). Агент ШІ або людина читає скани справи, а результат — **банка**: локальна база SQLite з особами, подіями, зв'язками, місцями й сумнівами, яку легко залити в генеалогічну базу.

Головне — щоб інструментом масово користувалися і щоб з нього виходило якомога більше придатних даних: перевірених, зі сканом на кожен запис, з виміряним відсотком помилок.

## Користувачі
- **Волонтери з AI Harness** (Claude Code та інші): ставлять плугін і читають справи своєю моделлю.
- **Генеалоги без технічних навичок**: користуватимуться вебом без інсталяції. Його поки не робимо, але ядро пишемо так, ніби він уже є.

## Межі
- **Іменник — усе до банки:** отримання сканів, читання, банка, перегляд у Гортачі, вимір помилок.
- **Заливка банки в базу — не тут.** Grapa ([github.com/solvek/grapa](https://github.com/solvek/grapa)) заливає банки у свою базу своїми інструментами. Іменник не знає її схеми й не має до неї прямого доступу; пізніше з'явиться необов'язковий MCP-конектор (знайти джерело, підказки, надіслати банку).
- Банки й скани справ з реальними людьми в репозиторій не потрапляють; приклади й тести — на вигаданих даних.

## Будова
- **Бібліотека** (`src/…`): типізовані функції без `process.argv`, `console` і шляхів.
- **Над нею — тонкі оболонки:** CLI, MCP-сервер (для Harness), локальний веб (Гортач), пізніше — сайт.
- **Модель ШІ задається ззовні:** у Harness інструменти кличе модель користувача; зі своїм ключем Іменник веде власний цикл агента з тими самими інструментами.
- **Сховище сканів і банок задається ззовні:** тека на диску зараз, сховище сервера потім.
- **Банка — формат обміну:** нумеровані міграції, версія схеми, власний словник типів (події, зв'язки, атрибути).
- **Сегментатор рядків** (скан → полігони й бокси рядків) — окремий змінний компонент зі своїм інтерфейсом; Kraken на Python — лише окремим процесом і за бажанням, для вебу — модель у ONNX.
- Мова — TypeScript; вирізки сканів — бібліотекою `sharp`, без окремої інсталяції ImageMagick.

## Етапи
Спершу переносимо з Grapa те, що вже працює, без змін поведінки; нове додаємо поетапно. Кожен етап — одна чи кілька змін OpenSpec.

| Етап | Що | Стан |
|---|---|---|
| 0. Заготовка | репозиторій, `AGENTS.md`, ліцензія Apache 2.0, TypeScript, ESLint, Prettier, Vitest, OpenSpec | ✓ |
| 1. Переїзд | з Grapa з історією: ядро індексації (банка, читання, `ingest`, `hints`, `sample`, `review`, `run`, `dump`, скани), Гортач, читання дерев FamilySearch у банку з правилом живих, завантаження сканів FamilySearch (як є), словники, документи; специфікації `scan-indexing`, `scan-review` і нова `familysearch-tree-bank`. Зміна `move-from-grapa` | — |
| 2. Банка як пакет | `schema_version` і перевірка версії, власний словник типів, публічний API для заливки; Grapa підключає Іменник пакетом (у Grapa — своя зміна) | — |
| 3. Плугін і MCP | skill + MCP-сервер з інструментами (`crop`, `ingest`, `hints`, `sample` …); вирізки через `sharp`; завантаження сканів FamilySearch — на TS за правилами проєкту | — |
| 4. Каталог бланків | бланки як дані: колонки, ролі, події, перевірки (лічильники, підсумки, «те саме, що вище», пара ліва–права сторінка); визначення типу справи чи її частини | — |
| 5. CSV ↔ банка | таблиця записів з шапкою (формат record-sheet з Grapa) в обидва боки | — |
| 6. Сегментатор | спершу проба Kraken `blla` на кількох справах; за результатом — ONNX у Node чи класичний аналіз таблиць | — |
| 7. Підказки | чужі індекси й HTR (експорт UaRoots, транскрипції) як шар підказок для читання, не як дані | — |
| 8. Надсилання банок | MCP-конектор до бази (а через нього, можливо, і підказки прізвищ та місць замість власних словників), умови надсилання (безстрокова ліцензія з комерційним використанням), перевірки при прийманні | — |
| 9. Веб | сайт без інсталяції над тим самим ядром: завантаження сканів, читання з ключем користувача, Гортач, спільна робота | — |
