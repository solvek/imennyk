# AGENTS.md

Instructions for coding agents (Claude Code, Cursor, Codex, …) working on Imennyk.

The human owner does not review code. **Types, linters and tests are the reviewer.** Treat every rule below as mandatory.

## Project
Imennyk (Ukrainian «Іменник») indexes people in archival documents: an agent or a person reads the scans of a case, and the result is a **bank** — a local SQLite database of persons, events, ties, places and doubts, ready to be loaded into a genealogy database. It is open source (Apache 2.0). Read before working:
- `docs/overview.md` — goals, boundaries, stages
- `openspec/specs/` — behaviour the tool guarantees

Imennyk was split out of [Grapa](https://github.com/solvek/grapa), a genealogical research platform; Grapa loads banks into its database (the well) and stays a separate project. Imennyk knows nothing about Grapa's database: it does not import its code, its schema or its connection. Loading a bank into a database is the job of that database's own tools.

Documentation in `docs/` and OpenSpec artifacts are written in Ukrainian. Code, identifiers, comments and commit messages are in English.

Glossary (as in Grapa):
- **банка** (bank) — a local SQL database with data prepared for loading: persons, events, ties, places, the source. One archival case — one bank (`case.sqlite`).
- **банкувати** — prepare a bank for a task; when the task needs scans, this includes getting, reading and indexing them.
- **індексування** — reading scans and writing what is read into the bank: persons, events, ties, doubts.
- **прогін** (run) — one reading pass in a bank: one model, one part of a case.
- **Гортач** — a local web app to review a bank after indexing: doubts, sample, error rate.
- **скан** — an image of a page or a spread of a case; in the bank, a row of `scan`.

## Rules
- **A library module, not a script.** Logic lives in `src/…`: functions take typed input and return typed results; no `process.argv`, `console` or file paths inside the logic.
- **A thin CLI on top** (`src/<tool>/cli.ts`, run by a `pnpm` script) only parses arguments, reads files and prints. The MCP server and the web app call the same functions.
- **The core does not depend on local programs or paths** (ImageMagick, Chrome, fixed folders): storage of scans and banks and the AI model are passed in from outside, so that a hosted web version can run the same core later.
- **The bank schema is numbered SQL migrations** in `src/indexing/migrations/` (once the code is moved); data rules live in the schema (CHECK, foreign keys) as far as SQLite allows.
- **Source-specific choices are input, not code.** Decisions about one particular source go into an options object or a file passed to the tool.
- **People from family trees:** no living person is ever written into a bank from a family tree (FamilySearch, GEDCOM, …); a person whose state is unknown is left out and named in the report. People named in archival documents may all be written.
- **No personal data in the repository.** Tests, examples and demos use fictional people and fictional scans. Banks and scans of real cases are kept outside the repository.

## Specs and changes (OpenSpec)
Behaviour the tool guarantees is described in `openspec/specs/`; every non-trivial change goes through OpenSpec (`openspec/config.yaml` has the project rules).
- Propose with `/opsx:propose`, implement with `/opsx:apply`, finish with `/opsx:archive`.
- The skills and commands in `.claude/` and `.cursor/` are generated by `openspec init`/`openspec update`: do not hand-edit them.
- OpenSpec does not replace `docs/`: design and stages stay there.

## Language and tooling
- **TypeScript** in strict mode for all code. No Python, except an optional line segmenter run as a separate process (`docs/overview.md`).
- Runtime: current Node.js LTS. Package manager: pnpm.
- `tsconfig`: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noFallthroughCasesInSwitch`.
- Linting: ESLint with `typescript-eslint` `strict-type-checked` + `stylistic-type-checked`. Formatting: Prettier.
- Tests: Vitest.
- Bank: SQLite through `node:sqlite`.

## Type safety
- No `any`. No `as` casts, except right after runtime validation at a boundary.
- Validate all external input (files, LLM output, rows from untyped queries) with schemas at the boundary.
- No non-null assertions (`!`). Handle `undefined` explicitly.
- Never use `@ts-ignore` / `@ts-expect-error` or disable lint rules to get a green build. If it is truly unavoidable, add a comment explaining why and mention it in the commit message.

## Tests
- Every rule of the bank and of reading has tests.
- Every bug fix starts with a failing test that reproduces it.
- Tests must be deterministic: no reliance on wall-clock time, randomness or network without control.
- Do not delete, skip or weaken an existing test to make a change pass.

## Definition of done
Before every commit, all of these must pass:
```
pnpm typecheck
pnpm lint
pnpm test
```
If a check cannot pass, do not commit; report what fails and why.

## Commits
- Small, focused commits; one logical change per commit.
- Message: imperative summary line, then a short body explaining *why* when it is not obvious.
- Work on `main` unless the owner asks for a branch or pull request.
